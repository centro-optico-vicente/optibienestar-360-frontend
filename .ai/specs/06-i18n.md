# 06 — i18n (Internacionalización)

## Configuración

```typescript
// nuxt.config.ts
modules: ['@nuxtjs/i18n'],
i18n: {
  locales: [
    { code: 'es', name: 'Español', file: 'es.json' },
    { code: 'en', name: 'English', file: 'en.json' },
  ],
  defaultLocale: 'es',
  strategy: 'no_prefix',  // no agregar /es/ a URLs (app SPA tras login)
  lazy: true,
  langDir: 'locales/',
}
```

> **Bilingüe desde el día 1.** El backend ya devuelve `ProblemDetail` y correos
> localizados en `en`, así que el frontend nace con `es` **y** `en` (mismas keys en
> ambos bundles). Los archivos viven en `i18n/locales/{es,en}.json`.

## URLs públicas en dos idiomas

La estrategia global sigue siendo `no_prefix` (las rutas autenticadas no cambian). Solo las **pantallas públicas** tienen par en inglés ([spec 12 del hub](https://github.com/centro-optico-vicente/centro-optico-vicente/blob/main/.ai/specs/12-url-conventions.md)): el español es la canónica y la inglesa muestra **la misma página en inglés** (alias de ruta con `definePageMeta({ alias })`, no redirección).

```
/                    ↔ /en
/aliados             ↔ /en/allies
/aliados/{uuid}      ↔ /en/allies/{uuid}
/afiliarse           ↔ /en/join            (?ref= del QR impreso se conserva)
/recuperar-clave     ↔ /en/forgot-password
/restablecer-clave   ↔ /en/reset-password  (?token= se conserva)
```

- El mapa vive en `app/utils/publicRoutes.ts` (`PUBLIC_ROUTE_PAIRS`, `publicPathLocale`, `localizePublicPath`, `toPublicLocalePath`). `auth.global.ts` lo usa para decidir qué es público (por eso `/en/allies` es público y `/allies` no).
- `middleware/public-locale.global.ts`: en una pantalla pública **la URL manda** (`/en/...` → `en`, ruta en español → `es`); en las autenticadas no toca el idioma, y al salir de una pública restaura la preferencia del usuario. `useAppLocale` no aplica la pista pre-login ni la preferencia guardada mientras la URL decide.
- `LocaleSwitcher` (en `layouts/auth.vue` y `layouts/default.vue`): en una pantalla pública, además de cambiar el idioma, navega a la URL par conservando query y hash.
- Enlaces entre pantallas públicas: `usePublicPath()` (`publicPath('/recuperar-clave')` → `/en/forgot-password` en inglés). Logout y sesión vencida van al login del idioma activo (`currentLoginPath()`).
- `usePublicRouteHead()` (desde `app.vue`) agrega `rel="canonical"` (URL del idioma mostrado) y `rel="alternate"` `hreflang` `es`, `en` y `x-default` (→ español), sin query.
- nginx (`docker/default.conf`) sirve `/en/**` con el fallback SPA (200, sin redirección); el smoke test de CI lo verifica.

## Reglas

- **Toda string visible al usuario debe estar en `es.json` + `en.json`** (mismas keys) — no hardcodear en componentes
- **Paridad verificada en CI:** `scripts/check-i18n-parity.mjs` (`pnpm i18n:check`, sin dependencias) falla el job si una key existe en un bundle y no en el otro, si cambia el tipo de valor, si hay traducciones vacías o si los placeholders `{name}` de un mensaje difieren entre idiomas. Al agregar un idioma, sumarlo a `OTHERS` en el script.
- **Errores de negocio NO se traducen en el cliente** — los `ProblemDetail` del backend ya llegan localizados; en el cliente solo se traducen textos UI-only (labels, botones, títulos, vacíos, validaciones zod)
- **Formato NO se ata al locale de UI** — moneda/fecha vía `useFormatters` siguen la convención `es-VE` aunque la interfaz esté en inglés ([ADR 0010](../decisions/loc-0010-localization-venezuela.md))
- **Nested keys por dominio** — facilita encontrar y mantener
- **NO incluir HTML en strings** — usar componentes para markup
- **Pluralización:** usar Vue I18n syntax `'{count} afiliado | {count} afiliados'`
- **Interpolación:** `'Hola, {name}'` + `t('greeting', { name: 'Juan' })`

## Formato de fechas / números

Usar `useFormatters` composable + i18n:

```typescript
// composables/useFormatters.ts
export const useFormatters = () => {
  const formatCurrency = (amount: number, currency = 'USD') =>
    new Intl.NumberFormat('es-VE', { style: 'currency', currency }).format(amount);

  const formatDate = (date: string | Date, format: 'short' | 'long' = 'short') => {
    const d = typeof date === 'string' ? new Date(date) : date;
    if (format === 'long') {
      return new Intl.DateTimeFormat('es-VE', { day: 'numeric', month: 'long', year: 'numeric' }).format(d);
    }
    return new Intl.DateTimeFormat('es-VE').format(d);
  };

  const formatRelative = (date: string | Date) => {
    // "hace 3 días", "en 2 semanas"
    const rtf = new Intl.RelativeTimeFormat('es-VE', { numeric: 'auto' });
    // ... lógica
  };

  return { formatCurrency, formatDate, formatRelative };
};
```

Uso:
```vue
<script setup>
const { formatCurrency, formatDate } = useFormatters();
</script>
<template>
  <td>{{ formatCurrency(payment.amount) }}</td>
  <td>{{ formatDate(membership.next_due_date, 'long') }}</td>
</template>
```
